# Behavioral models

Quint 0.33.1 translates these finite models to TLA+ for TLC. Use Java 21.
Quint downloads its backend on first use and starts a local translation
server. Run from the repository root:

```sh
npx --yes --package=@informalsystems/quint@0.33.1 quint verify formal/quint/aggregation.qnt --backend=tlc --main Aggregation --invariants Precedence
npx --yes --package=@informalsystems/quint@0.33.1 quint verify formal/quint/observation.qnt --backend=tlc --main Observation --invariants ObservationContract
npx --yes --package=@informalsystems/quint@0.33.1 quint verify formal/quint/acquisition.qnt --backend=tlc --main Acquisition --invariants AcquisitionContract
npx --yes --package=@informalsystems/quint@0.33.1 quint verify formal/quint/inspection.qnt --backend=tlc --main Inspection --invariants ExitContract
cargo test --locked --workspace --all-features
```

The [CI job](../../.github/workflows/ci.yml) type-checks and verifies each model
and requires an invariant violation from its negative control. To inspect the
counterexample locally, rerun a command with `Mutant` appended to the main
module name. The negative control requires TLC to report an invariant violation.

| Model | Finite domain and invariant | Rust correspondence |
| --- | --- | --- |
| [Aggregation](aggregation.qnt) | A subset of the three package outcomes and an input-error event. Exact precedence is specified independently of the rank fold. | [Aggregation tests](../../crates/taloon-decisions/tests/aggregate.rs) run one canonical package list for every event set. proptest varies list order and multiplicity. |
| [Observation](observation.qnt) | Two distinguishable payloads and repeated record/consume transitions. A bounded history distinguishes empty, singleton and duplicate segments and specifies the consume result. | [Observation tests](../../crates/taloon-decisions/tests/observation.rs) replay named traces through `Observation`. proptest compares arbitrary payload histories against a segmented-history oracle. |
| [Remote acquisition](acquisition.qnt) | Network mode, strength requirement, usable cache outcome and usable sidecar outcome. Offline blocks remote requests, strong requirements bypass sidecars, and incomplete online sidecars route to the archive. | [Acquisition fixtures](../../src/acquisition/http_tests.rs) test the same observable routes, including `offline_strong_policy_rejects_weak_only_cache`, `online_strong_policy_upgrades_weak_only_cache`, and `legacy_supplement_cached_sidecar_respects_network_mode`. |
| [Inspection exit](inspection.qnt) | Two required artifacts, each missing, successful, failed, or duplicated. Only exactly one successful observation per artifact allows permission and warning policy to determine the exit. | [Inspection tests](../../tests/inspection.rs) cover all 128 model inputs with real wheel bytes and parsed policy. PBT varies the order and multiplicity of results. The [CLI property](../../tests/cli.rs) checks the process and JSON exit codes. |

In the acquisition model, cache and sidecar outcomes enter after provenance
and strength validation. The routing decision reaches a terminal phase in at
most two model steps.
An archive phase denotes a fetch attempt. The Rust tests exercise HTTP
responses, cache writes, index parsing, concurrency and the final verdict.

Local TLC with Java 21 on macOS arm64 checked 16 aggregation, 7 observation,
108 acquisition, and 256 inspection states. The mutants yielded an incomplete
result overwritten by a violation, a duplicate returned as a singleton, an
offline cache miss reaching a network route, and an inspection with duplicate
evidence reaching the permission decision, respectively.

See the [verification strategy](../../docs/development/knowledge/verification-strategy.md#verification-across-taloon)
for how these models fit into the whole-project checks.

## Acquisition-to-report lifecycle

[Lifecycle](lifecycle.qnt) models repeated checks of two required external
packages. A cache carries the parent archive and up to two content digests
for its transitive child. Each check can clear the cache, change the locked
child digest, switch network mode, change policy, or supply a duplicate
result. An online cache miss can receive the expected wheel, a temporary
503 followed by the expected wheel, an older wheel, or a 404. The invariant
independently computes which digests may persist, archive attempts, cache
hits, each package verdict, and the final exit status.

```sh
npx --yes --package=@informalsystems/quint@0.33.1 quint verify formal/quint/lifecycle.qnt --backend=tlc --main Lifecycle --invariants LifecycleContract
npx --yes --package=@informalsystems/quint@0.33.1 -c 'bash formal/quint/replay.sh'
```

The replay script runs eight fixed Quint simulation seeds for 24 operations
each. It normalizes the ITF output to [a versioned JSON Lines corpus](../../tests/fixtures/oracle/lifecycle.jsonl)
and checks that the generated bytes match. Use `bash formal/quint/replay.sh
--generate` with Quint 0.33.1 on PATH to update the corpus after reviewing a
model change. CI checks the corpus and replays it. Ordinary workspace tests
also replay the committed corpus without requiring Quint or Java.

The [Rust adapter](../../src/acquisition/http_tests/lifecycle.rs) parses
uv.lock documents with three dependency graphs: a chain, two direct
dependencies, and a graph where the same target is both direct and transitive.
It checks the reported path follows the expected shortest route. It uses real wheel bytes, the production retry loop, a disk
cache shared across checks, and the public inspection/report API. A scripted
transport supplies HTTP responses. The adapter compares both package
statuses, the transitive diagnostic path, archive attempts, cache hits,
cached digests, and exit status at each step. The fixture covers successful
retries, stale responses, warm offline reuse, offline misses with only an old
digest cached, populated-cache clears, and duplicate results even when both
archives are available. The lifecycle is sequential at the check boundary. The replay covers two
external packages in each graph.

TLC checked 640 reachable states on macOS arm64 with Java 21. The mutant
accepted a cached child for the old digest during an offline check for the new
digest. TLC rejected that transition. The Rust adapter replayed the 192 steps
for each of the three graphs.

## Concurrent index initialization

[IndexConcurrency](index_concurrency.qnt) explores two workers competing
for a single package index snapshot. A completed load publishes a shared
success or error. A panic ends the failing worker and lets the other claim
initialization. The invariant checks that workers reuse the published result
and that every load attempt belongs to a completed, panicked, or active
initializer. The negative control drops a completed error instead of sharing it.

```sh
npx --yes --package=@informalsystems/quint@0.33.1 quint verify formal/quint/index_concurrency.qnt --backend=tlc --main IndexConcurrency --invariants SnapshotContract
cargo test --locked --bin taloon index_snapshot
cargo test --locked --bin taloon terminal_index_failure_is_shared_but_each_archive_is_verified
cargo test --locked --bin taloon panicked_index_initializer_releases_waiters_and_keeps_traffic
```

The [Rust acquisition tests](../../src/acquisition/http_tests.rs) observe a
shared successful fetch, a shared terminal error with archive fallback, and
retry after a controlled initializer panic. The model abstracts one package
endpoint and two workers. Rust fixtures also exercise multiple endpoints,
parallel workers, and loopback TLS.
