# Behavioral models

Quint 0.33.1 translates these finite models to TLA+ for TLC. Use Java 21.
Quint downloads its backend on first use and starts a local translation
server. Install the locked Node dependencies and run from the repository root:

```sh
npm ci --prefix formal/quint --ignore-scripts --no-audit --no-fund
quint=./formal/quint/node_modules/.bin/quint
"$quint" verify formal/quint/aggregation.qnt --backend=tlc --main Aggregation --invariants Precedence
"$quint" verify formal/quint/observation.qnt --backend=tlc --main Observation --invariants ObservationContract
"$quint" verify formal/quint/acquisition.qnt --backend=tlc --main Acquisition --invariants AcquisitionContract
"$quint" verify formal/quint/inspection.qnt --backend=tlc --main Inspection --invariants ExitContract
cargo test --locked --workspace --all-features
```

The [CI job](../../.github/workflows/ci.yml) type-checks and verifies each model
and requires an invariant violation from its negative control. To inspect the
counterexample locally, rerun a command with `Mutant` appended to the main
module name. The negative control requires TLC to report an invariant violation.

| Model | Finite domain and invariant | Rust correspondence |
| --- | --- | --- |
| [Aggregation](aggregation.qnt) | A subset of the three package outcomes and an input-error event. Exact precedence is specified independently of the rank fold. | [Aggregation tests](../../crates/taloon-decisions/tests/aggregate.rs) run one canonical package list for every event set. proptest varies list order and multiplicity. |
| [Observation](observation.qnt) | Two distinguishable payloads and repeated record/consume transitions. A bounded history distinguishes empty, singleton and duplicate segments and specifies the consume result. | [Observation tests](../../crates/taloon-decisions/tests/observation.rs) replay named traces through `Observation`. proptest compares arbitrary payload histories against a segmented-history oracle. |
| [Remote acquisition](acquisition.qnt) | Network mode, strength requirement, usable cache outcome and usable sidecar outcome. Offline blocks remote requests, strong requirements bypass sidecars, and incomplete online sidecars route to the archive. | [Acquisition fixtures](../../src/acquisition/http_tests.rs) test the same observable routes, including `offline_strong_policy_rejects_weak_only_cache`, `online_strong_policy_upgrades_weak_only_cache`, and `legacy_supplement_cached_sidecar_respects_network_mode`. |
| [Inspection exit](inspection.qnt) | Two required artifacts, each missing, successful, failed, or duplicated. Only exactly one successful observation per artifact allows permission and warning policy to determine the exit. | [Inspection tests](../../tests/inspection.rs) cover all 128 model inputs with real wheel bytes and parsed policy. PBT varies the order and multiplicity of results. The [CLI property](../../tests/cli.rs) checks the process and JSON exit codes. |

In the acquisition model, cache and sidecar outcomes enter after provenance
and strength validation. The routing decision reaches a terminal phase in at
most two model steps.
An archive phase denotes a fetch attempt. The Rust tests exercise HTTP
responses, cache writes, index parsing, concurrency and the final verdict.

Local TLC with Java 21 on macOS arm64 checked 16 aggregation, 7 observation,
108 acquisition, and 256 inspection states. The mutants yielded an incomplete
result overwritten by a violation, a duplicate returned as a singleton, an
offline cache miss reaching a network route, and an inspection with duplicate
evidence reaching the permission decision, respectively.

See the [verification strategy](../../docs/development/knowledge/verification-strategy.md#verification-across-taloon)
for how these models fit into the whole-project checks.

## Acquisition-to-report lifecycle

[Lifecycle](lifecycle.qnt) models repeated checks of two required external
packages. A cache carries the parent archive and up to two content digests
for its transitive child. Each check can clear the cache, change the locked
child digest, switch network mode, change policy, or supply a duplicate
result. An online cache miss can receive the expected wheel, a temporary
503 followed by the expected wheel, an older wheel, or a 404. The invariant
independently computes which digests may persist, archive attempts, cache
hits, each package verdict, and the final exit status.

```sh
"$quint" verify formal/quint/lifecycle.qnt --backend=tlc --main Lifecycle --invariants LifecycleContract
bash formal/quint/replay.sh "$quint"
```

The replay script runs eight fixed Quint simulation seeds for 24 operations
each. It normalizes the ITF output to [a versioned JSON Lines corpus](../../tests/fixtures/oracle/lifecycle.jsonl)
and checks that the generated bytes match. Use `bash formal/quint/replay.sh --generate "$quint"` to update the corpus
after reviewing a model change. CI checks the corpus and replays it. Ordinary workspace tests
also replay the committed corpus without requiring Quint or Java.

The [Rust adapter](../../src/acquisition/http_tests/lifecycle.rs) parses
uv.lock documents with three dependency graphs: a chain, two direct
dependencies, and a graph where the same target is both direct and transitive.
It checks the reported path follows the expected shortest route. It uses real wheel bytes, the production retry loop, a disk
cache shared across checks, and the public inspection/report API. A scripted
transport supplies HTTP responses. The adapter compares both package
statuses, the transitive diagnostic path, archive attempts, cache hits,
cached digests, and exit status at each step. The fixture covers successful
retries, stale responses, warm offline reuse, offline misses with only an old
digest cached, populated-cache clears, and duplicate results even when both
archives are available. The lifecycle is sequential at the check boundary. The replay covers two
external packages in each graph.

TLC checked 640 reachable states on macOS arm64 with Java 21. The mutant
accepted a cached child for the old digest during an offline check for the new
digest. TLC rejected that transition. The Rust adapter replayed the 192 steps
for each of the three graphs.

## Concurrent index initialization

[IndexConcurrency](index_concurrency.qnt) explores two workers competing
for a single package index snapshot. A completed load publishes a shared
success or error. A panic ends the failing worker and lets the other claim
initialization. The invariant checks that workers reuse the published result
and that every load attempt belongs to a completed, panicked, or active
initializer. The negative control drops a completed error instead of sharing it.

```sh
"$quint" verify formal/quint/index_concurrency.qnt --backend=tlc --main IndexConcurrency --invariants SnapshotContract
cargo test --locked --bin taloon index_snapshot
cargo test --locked --bin taloon terminal_index_failure_is_shared_but_each_archive_is_verified
cargo test --locked --bin taloon panicked_index_initializer_releases_waiters_and_keeps_traffic
```

The [Rust acquisition tests](../../src/acquisition/http_tests.rs) observe a
shared successful fetch, a shared terminal error with archive fallback, and
retry after a controlled initializer panic. The model abstracts one package
endpoint and two workers. Rust fixtures also exercise multiple endpoints,
parallel workers, and loopback TLS.

## Shared disk cache

[SharedCache](shared_cache.qnt) models two writers for different locked
digests of an archive at the same URL. A writer creates an unpublished
temporary file, syncs its contents, and publishes it. Lookups observe only
published records for their digest. A reader that already holds an open
file can finish after its directory entry is removed. A writer can publish
after a clear, including when it was already staging the record at the
time of the clear.

```sh
"$quint" verify formal/quint/shared_cache.qnt --backend=tlc --main SharedCache --invariants PublicationContract
bash formal/quint/replay.sh "$quint"
```

The model treats a completed clear as one action between writer and reader
checkpoints. It covers cross-digest reads and one open reader at a time.
The Rust suite also exercises concurrent replacement of the same digest
and rejection of truncated or invalid records.

TLC explored 254 states and rejected a mutant that made an unpublished
record visible at temporary-file creation. The [generated corpus](../../tests/fixtures/oracle/shared-cache.jsonl)
contains eight 32-step traces. The [Rust replay](../../src/acquisition/http_tests/cache_interleaving.rs)
uses separate real acquisition batches sharing a disk cache. Test-only
checkpoints pause at temporary-file creation, immediately before publication,
and after opening a published record. The adapter verifies the clear count,
offline observations for both digests after each action, and completion of
paused readers and writers. Traces include simultaneous staging, clear
during staging and immediately before publication, and reads that finish
after clear has removed the opened record.

## Extras on a cyclic dependency path

[Extras](extras.qnt) explores the eight combinations of three choices on a
fixed graph. The root can activate `hub[feature]` directly, the back edge
from `bridge` can activate it on return to `hub`, and the root can have
a shortcut to the target. The model compares its queue traversal with the
shortest path derived directly from the shape of the graph.

```sh
"$quint" verify formal/quint/extras.qnt --backend=tlc --main Extras --invariants ExtrasContract
bash formal/quint/replay.sh "$quint"
```

TLC checked 30 reachable states. The mutant merges `hub` and
`hub[feature]` in its visited set. TLC found a counterexample when the back
edge alone activates the extra. The queue discards the second visit and
loses the only route to the target.

The [generated result corpus](../../tests/fixtures/oracle/extras.jsonl) contains
all eight cases. The [Rust replay](../../tests/resolution_paths.rs) renders each
case as uv.lock, calls the public resolver, and checks the path and extras
annotation. In an isolated Rust copy, removing extras from the visited key caused the
return-edge-only replay to fail. The [generated graph properties](../../tests/resolution_graphs.rs)
cover larger cyclic graphs, multiple entries and multiple active extras.

## Conditional edges to same-name locked packages

[LockedForks](locked_forks.qnt) checks 192 combinations of exact version,
source, version constraint, origin kind, and marker presence over three
same-name locked candidates. Independent tables define the candidate set for
each selector field. A regular dependency requires exactly one match. An
ambiguous or unmatched manifest group contributes no path, and the locked
inventory remains available for inspection. A marker on a selected edge is
preserved in its diagnostic path.

```sh
"$quint" verify formal/quint/locked_forks.qnt --backend=tlc --main LockedForks --invariants UniqueIdentity
bash formal/quint/replay.sh "$quint"
```

TLC checked all 192 states and found a counterexample when the model
ignored the source selector. The [generated corpus](../../tests/fixtures/oracle/locked-forks.jsonl)
contains the complete finite domain. The [Rust replay](../../tests/resolution_matching.rs)
renders each input into uv.lock, checks rejection or the exact locked
inventory, and compares the selected identity and the marker on its path.
Removing the source filter in an isolated Rust copy caused 52 replays to fail.
The model uses two valid range predicates and a fixed version/source
inventory. Rust tests separately cover malformed selectors and variation in
unrelated records.

## Ties between annotated dependency paths

[PathTies](path_ties.qnt) compares competing routes through different
packages, different markers on the same package, and different sets of
extras. It varies whether a shorter route exists, whether the hub offers
an ordinary edge, and whether the lock lists the same records and edges in
reverse order. When the shortest distance ties, the model orders root edges
by package, marker, and extra labels. At a hub it considers the ordinary
edge before the active optional groups, then visits those groups in
normalized extra order.

```sh
"$quint" verify formal/quint/path_ties.qnt --backend=tlc --main PathTies --invariants CanonicalPath
bash formal/quint/replay.sh "$quint"
```

TLC explored 32 states and rejected a mutant that used lock listing order
for competing root edges. The [generated cases](../../tests/fixtures/oracle/path-ties.jsonl)
include both the ordinary root and its development group. The
[Rust replay](../../tests/resolution_paths.rs) compares the winning route
and each step's marker and extra labels through the public resolver.
Removing the canonical edge sort in an isolated Rust copy caused 12
replays to fail. The model ranks complete routes on a fixed graph. The generated graph
property exercises shortest paths on larger shapes.

## Hash-scoped policy and evidence

[ScopedPolicy](scoped_policy.qnt) checks 96 combinations of exception scope,
clarification hash, allow or deny mode, global listing, and evidence
strength. The original declaration is a custom unit. The clarification, when
its digest matches, substitutes MIT. A matching custom exception or
clarification requires archive proof. A global MIT deny retains precedence
over the exception after clarification.

```sh
"$quint" verify formal/quint/scoped_policy.qnt --backend=tlc --main ScopedPolicy --invariants ScopeContract
bash formal/quint/replay.sh "$quint"
```

TLC explored 96 states and detected a mutant that applied an exception to the
wrong digest. The [generated corpus](../../tests/fixtures/oracle/scoped-policy.jsonl)
drives the public [Rust inspection replay](../../tests/inspection.rs). It
compares the requested proof, artifact and report status, effective
expression, and ordered override identifiers. Removing the exception hash
check in an isolated Rust copy caused 20 replays to fail. The model fixes two atomic
units and a single exception and clarification. Lean and Rust properties
cover Boolean expressions and the surrounding inspection contracts.

## Unused policy warnings

[UnusedPolicy](unused_policy.qnt) checks 128 combinations on two locked
packages. Alpha declares a three-term OR. Beta declares ISC, which a
hash-matching clarification replaces with BSD-3-Clause. Independently
vary allow or deny mode, whether ISC is listed, whether each exception
matches, and whether the beta observation is present, missing, repeated,
or failed.

```sh
"$quint" verify formal/quint/unused_policy.qnt --backend=tlc --main UnusedPolicy --invariants WarningContract
bash formal/quint/replay.sh "$quint"
```

All units in the effective OR expression count as used. Exact
package/digest matches account for exceptions, and a matching clarification
accounts for its own digest. Incomplete reports suppress unused warnings.
Completed reports expose warnings in message order. Strict warning mode
escalates a compliant exit to 1 when warnings exist. Violations exit 1 and
incomplete reports exit 2. The first replay exposed the distinction between
policy emission order and report order. The model follows the public report
order.

TLC explored 128 states and found a counterexample when accounting retained
only the first OR unit. The [generated corpus](../../tests/fixtures/oracle/unused-policy.jsonl)
drives the [Rust replay](../../tests/policy_usage.rs), which checks exact
warning messages, warning severity and normal and strict exit codes.
Retaining only the first OR unit in an isolated Rust copy caused all 32
complete-inspection replays to fail.

## Grouping evidence in a description report

[DescriptionEvidence](description_evidence.qnt) checks 324 combinations
across two artifacts for the same package. Inputs cover archive and index
proof, standard and custom declarations, malformed declarations, missing and
duplicate results, acquisition failure, and a valid archive for the wrong
digest. The model also varies arrival order and a result for an unselected
artifact.

```sh
"$quint" verify formal/quint/description_evidence.qnt --backend=tlc --main DescriptionEvidence --invariants DescriptionContract
bash formal/quint/replay.sh "$quint"
```

Results group by exact interpreted expression. Each group retains all
matching artifact IDs. An unresolved artifact contributes to the unknown
count. Foreign results make the report incomplete while successful
observations remain visible. TLC explored 324 states and detected a mutant
that accepted the first of duplicate results.

The [generated cases](../../tests/fixtures/oracle/description-evidence.jsonl)
drive the public [description replay](../../tests/description.rs) with real
wheel and sidecar evidence. The adapter checks the diagnostic codes,
unknown count, exact group membership, and exit status. Keeping the first
of duplicate observations in an isolated Rust copy caused 68 replays to fail.
The Lean selection corpus separately exercises graph selection.

## Sidecar admission and archive fallback

[SidecarFallback](sidecar_fallback.qnt) checks 240 combinations of index
advertisement, metadata response, archive response, minimum proof, and
index representation. An index offer must match the complete URL and
locked archive digest and be unambiguous. The downloaded metadata must
match its advertised digest and package identity. A request for archive
proof bypasses the index and sidecar.

```sh
"$quint" verify formal/quint/sidecar_fallback.qnt --backend=tlc --main SidecarFallback --invariants FallbackContract
bash formal/quint/replay.sh "$quint"
```

TLC explored 240 states and detected a mutant that omitted the metadata
digest check. The [generated cases](../../tests/fixtures/oracle/sidecar-fallback.jsonl)
drive [Rust acquisition](../../src/acquisition/http_tests/sidecar_fallback.rs)
with scripted JSON and HTML index responses, real wheel bytes and a disk
cache. The adapter compares request counts, warnings, artifact errors,
interpreted expressions and retained proof. A second offline acquisition
checks reuse of successful evidence and the absence of usable evidence
after both acquisition paths fail. Removing the metadata digest check in
an isolated Rust copy caused six replays to fail.

The fixture covers cold online acquisition followed by offline reuse.
Separate models and Rust cases cover shared-cache interleavings, retry,
and reading bundled license files.

## Bundled license scans and cache reuse

[LegacyScan](legacy_scan.qnt) checks 16 scenarios of five acquisitions each.
A sidecar leaves an `UNKNOWN` or BSD legacy declaration pending. The archive
can supply matching license text, supply unusable text, declare a modern SPDX
expression, or contain a legacy declaration ineligible for supplementation.
The first archive request can fail, leaving the sidecar available for
offline inspection and allowing an online retry.

```sh
"$quint" verify formal/quint/legacy_scan.qnt --backend=tlc --main LegacyScan --invariants ScanContract
bash formal/quint/replay.sh "$quint"
```

TLC explored 80 states and detected a mutant that refreshed a completed
negative result. The [generated corpus](../../tests/fixtures/oracle/legacy-scan.jsonl)
drives the [binary acquisition replay](../../src/acquisition/http_tests/legacy_scan.rs).
The adapter opens a fresh acquirer on the same disk cache for each step.
It checks request counts, proof, declaration, interpretation origin and
diagnostic code. It also distinguishes a cached pending sidecar from
a completed archive observation. The final online step supplies a 404
for the archive, verifying that a completed negative result remains usable
as verified evidence without another fetch. Refetching completed negative
observations in an isolated Rust copy caused all eight negative scenarios
to fail.

The model abstracts the interpretation of four fixed archive outcomes.
Existing parser fixtures and properties exercise recognition and family
compatibility with additional inputs.

## HTTP redirects, retries, and authentication

[HttpRouting](http_routing.qnt) checks 96 combinations across six routes,
four retry prefixes, and four terminal responses. Routes include
same-origin redirects, a round trip through another host or port, an
HTTPS downgrade, and a redirect loop. Retry prefixes exercise 429, 503,
and partial transport failures. The invariant independently computes
the final attempt count and terminal outcome and checks credential
eligibility on every request.

```sh
"$quint" verify formal/quint/http_routing.qnt --backend=tlc --main HttpRouting --invariants RoutingContract
bash formal/quint/replay.sh "$quint"
```

TLC explored 656 states and detected a mutant that resumed authentication
after a return to the original origin. The [generated corpus](../../tests/fixtures/oracle/http-routing.jsonl)
supplies scripted responses and expected attempts. The
[Rust replay](../../src/acquisition/http_tests/http_routing.rs) invokes the
production HTTP wrapper, captures the requested URL and authorization,
and checks the terminal result, request counts, and downloaded bytes.
Synthetic credentials also distinguish explicit authorization from URL
userinfo. Reducing the retry budget from three attempts to two in an
isolated Rust copy caused 48 replays to fail. The transport is scripted.
Existing loopback tests exercise actual HTTP and TLS handling.

## Release reservation under a competing update

[ReleaseReservation](release_reservation.qnt) checks 32 schedules with a
fixed version floor and four linearly ordered source commits. A caller
reserves the third commit. An already reserved first commit is optional.
Another checkout may reserve the older, same, or newer commit immediately
before the caller's first push. The caller can also lose an acknowledgement
or encounter repeated rejected pushes. One schedule loses the acknowledgement
after the fifth push succeeds.

```sh
"$quint" verify formal/quint/release_reservation.qnt --backend=tlc --main ReleaseReservation --invariants ReservationContract
bash formal/quint/replay.sh "$quint"
uv run --frozen --no-sync pytest tests/test_release.py -k quint_replays_release_reservation
```

TLC checked 196 states and rejected a mutant that omitted the final read
after exhausting the push budget. The [generated cases](../../tests/fixtures/oracle/release-reservation.jsonl)
drive the [Python replay](../../tests/test_release.py) against a temporary
local bare Git repository and two working copies. The replay inserts a real
competing reservation before the stale push, and injects rejection or loss
of acknowledgement at the subprocess boundary. It checks the returned tag
or error, push count, exact stable-tag inventory, and ordering ref. It also
checks that a stale push leaves both refs as written by the competitor.
Omitting the final read in an isolated Python copy caused four replays
to fail. The [release procedure](../../docs/development/releases.md) describes hosted
reservation and publication.
